# OpenGL entry-point coverage

Generated by `node glbridge/tools/gen_gl_coverage.js`. Do not hand-edit:
the opcode set comes from the guest DLL, the handler set from the
executor's real dispatch table, and only the approximation list inside
the generator is maintained by hand.

Classes follow section 2.3 of the implementation plan:

- **A** -- really implemented.
- **B** -- approximated, because WebGPU cannot express it exactly. The
  code names the deviation in [README.md](README.md).
- **C** -- accepted with no effect: a hint, or something the guest DLL
  already resolved before it reached the wire (`glPushAttrib` keeps its
  own stack and sends only the differences).
- **MISSING** -- no handler at all. The plan's M7 exit condition is zero
  of these.

## What this table does not cover

The guest DLL exports more entry points than there are opcodes, because
many resolve entirely inside `openglproxy/opengl32_proxy.c` and never reach
the host: display lists are recorded and replayed there,
`glPushAttrib`/`glPopAttrib` operate on its shadow state and emit only
the differences, `GL_SELECT` and `GL_FEEDBACK` are software transforms
that never touch the GPU, and pixel-buffer-object pack/unpack offsets are
resolved before the transfer. Those belong to the guest's own tests.
